Firefly Flash

Build a cozy chain-reaction game from a completely empty screen, one small step at a time. No experience needed: if you can click and type, you can make this.

  • ⏱ About 90 minutes
  • 🌱 Total beginners welcome
  • 💻 Nothing to install — the code runs right on this page

Play it first

Press Play, then click once somewhere in the night sky. Your click sends out a flash of light. Every firefly the light touches flashes too, and their light can catch more fireflies. One click, one chain reaction. Light up enough fireflies to clear the night!

A window into the night

Every game needs a window to happen in. In js-game-zero, you make one with just a few lines. Here's your entire first program. Press Run:

A dark sky and a moon! Let's read it line by line.

  • WIDTH = 640; and HEIGHT = 400; set the size of the game window in pixels. They must be written in capitals, exactly like that, because the game looks for those exact names.
  • TITLE is the game's name. The words go inside quote marks, which makes them a string.

Paint the meadow

Let's add stars, hills and some ground. There's nothing new to learn here except two tricks: comments, and the order things are painted in.

  • Lines starting with // are comments. The computer ignores them; they're notes to remind people what the code does.
  • screen.rect(0, 350, WIDTH, 50, "#1b1846") draws a filled rectangle: its left edge's x, its top edge's y, its width, its height, and its colour. Notice we used WIDTH as the width, so the ground always stretches all the way across.
  • The hills are giant circles whose middles are below the bottom of the window (y = 470 when the window is only 400 tall). Only their tops poke up. Drawing off the edge is completely fine. It just gets cut off.
🖌️
Big idea: painting order

The computer paints in the order you write the lines, like painting on a real canvas. Things painted later cover things painted earlier. That's why the sky comes first and the ground comes last.

The game loop: make it fly

A picture is nice, but games move. Here's the secret behind every video game: the computer draws a picture, changes things a tiny bit, draws again, changes a tiny bit, draws again… about 60 times a second. Your eyes blend those pictures into motion. That's the game loop.

We added a second special function, update(dt). The game calls it every frame, just before draw(). update changes things, draw shows them.

  • vx and vy are the firefly's velocity: how many pixels it moves each second, across (x) and down (y). A negative vy means it flies up.
  • dt is the time since the last frame, in seconds. It's usually about 0.017 (one sixtieth of a second).
  • x += vx * dt; means "add vx × dt to x". Speed × time = distance, so each frame the firefly moves exactly as far as it should in that sliver of time.

Watch the Live values box while it runs: x and y change every frame!

🏁 Why multiply by dt?
Not every computer manages 60 frames a second. Pick a slower frame rate and watch two fireflies race. Each dot is one frame.
Top: x += 50 * dt — moves by time Bottom: x += 50 / 60 — moves by frame

At 60 frames a second they tie. Slow the frame rate down and the bottom firefly falls behind, because it only moves when a frame happens. The top one takes bigger steps when frames are rare, so it always arrives on time. That's why we multiply by dt: the game runs at the same speed on every computer.

What is dt?

It's a tiny slice of time, about 0.017 seconds. Multiplying a speed by it gives a distance.
Try the race above at a low frame rate: what does the top firefly use to take bigger steps?

Bounce! Making decisions

Our firefly needs to turn around at the edges of the sky. That means the code has to check something and decide. Enter the if statement.

🤔
Big idea: if

if (something is true) do this;. The part in brackets is a question with a yes-or-no answer. if (x < EDGE) asks "is x less than EDGE?". If yes, the rest of the line runs; if no, it's skipped.

  • const SKY_BOTTOM and const EDGE are constants: like variables, but they can never change. Giving numbers names makes the code easier to read. SKY_BOTTOM says much more than 330.
  • Math.abs turns any number positive: Math.abs(-50) is 50. So vx = Math.abs(vx) means "fly right now", and vx = -Math.abs(vx) means "fly left now".
🐞
Why not just flip the speed?

You might think vx = -vx ("go the other way") would do. But if the firefly ends up a little past the edge, it flips, still isn't back inside next frame, and flips again, wiggling in the wall forever. Math.abs always points it back toward the inside, so it can never get stuck.

The firefly is at x = 630. WIDTH is 640 and EDGE is 16. Which line changes its speed?

WIDTH - EDGE is 624, and 630 is bigger than that, so it turns left.
Work out WIDTH - EDGE first, then compare it with 630.

A swarm: lists and loops

One firefly is lonely. We want lots, but writing x1, y1, x2, y2… for each would be awful. Instead, we'll keep a list of fireflies and let loops do the repetitive work. We'll start with something simpler: a list of stars.

🧺
Big idea: objects and lists

An object bundles named values together: { x: 80, y: 60, size: 2 } is one star. Read a part with a dot: star.x.

A list (programmers say array) holds many values in order: [] is an empty list, and .push(…) adds something to the end.

Two kinds of loop do the repeating:

  • for (let i = 0; i < 70; i++) is a counting loop: start i at 0, keep going while i is less than 70, add one each time. The code inside runs 70 times, making 70 stars.
  • for (const star of stars) visits each item of a list in turn, calling it star while it's there. That's how every star gets drawn.

makeFirefly() builds one firefly object at a random spot and returns it: it hands the new firefly back to whoever called it. randomInt(25, 60) picks a whole number from 25 to 60, and randomChoice([-1, 1]) picks either −1 or 1, so each firefly heads off in a random direction.

moveFirefly(fly, dt) is our old movement code, but now it takes a firefly as an argument, so the same code moves any firefly we give it.

In the Live values box, what does fireflies[0] mean?

Programmers count from 0, so the first item is number 0, the second is number 1, and so on.
The number in square brackets picks an item by its position, and positions start at 0.

Cute sprites

Circles are fine, but we have art! Games keep their pictures in an images folder. Here's what comes with Firefly Flash:

  • An Actor is a picture you can move around. new Actor("moon", { center: [446, 74] }) loads images/moon.svg and puts its middle at (446, 74). Then moon.draw() paints it.
  • Actors already have x and y, and we can stick our own extras onto them, like fly.vx. So the rest of our code barely changed!
  • Giving an actor a list of images and an fps (frames per second) makes it flip between the pictures like a flip book. Two wing positions, twelve flips a second, and the wings flap.
  • screen.blit("meadow", [0, HEIGHT - 130]) draws a picture with its top-left corner at that spot. It's great for scenery that doesn't move.
🌊
Twinkle, twinkle

The stars now shimmer. Math.sin gives a number that swings smoothly between −1 and 1 as time goes on, like a wave. 150 + 100 × that swings between 50 and 250, and we use it as each star's see-through-ness (Math.round rounds it to a whole number for rgb). Each star starts at a different point of the wave, so they don't all blink together: twinkle: Math.random() * 6 picks a random start. Math.random() gives a random fraction between 0 and 1, so times 6 it's anywhere from 0 to 6.

So close! Picture names are always lowercase.

Click to flash

Now let's make the game listen to you. When you click, we'll send out a flash of light: a glowing circle that grows, shines for a moment, then fades away. Click the sky a few times:

  • onMouseDown(pos) is another special name: the game calls it whenever you click or tap. pos is a list of two numbers, where you clicked, so pos[0] is the x and pos[1] is the y.
  • let spark = null;: null means "nothing here yet". A click puts a new object in spark, and if (spark) only runs its code when there is one.
  • Each frame, update makes the spark older (spark.age += dt) and works out its size. Once it's older than FLASH_TIME, it's set back to null: gone.
  • drawLight paints a soft pool of light: three see-through circles, biggest first, then a thin ring around the edge. The ring uses screen.draw.circle, which draws only an outline, while screen.circle always fills.

The size comes from flashRadius(age), a function that answers a question: "how big is a flash that is this many seconds old?" It checks which part of its life the flash is in, and returns the answer. At the end, Math.max(0, …) picks the bigger of two numbers, so the size never drops below zero. Drag through time on this graph to see it:

📈 A flash's life
This graph reads the constants from the code above, so it changes when you do. Drag across it to pick an age.

With GROW_TIME = 0.3 and GLOW_TIME = 1.4, what does flashRadius(1.0) return?

1.0 isn't less than 0.3, so the first if is skipped. It is less than 0.3 + 1.4 = 1.7, so the second one returns full size.

Chain reaction!

Here's the heart of the game: when a firefly touches light, it lights up too, and its light can catch others. Click near a firefly and watch the chain spread:

How does the code know a firefly is touching a light? Two circles touch when the distance between their middles is less than their two radiuses added together. Drag the circles to feel it out:

🔵 Do they touch?
Drag the flash or the firefly. The dotted triangle shows how the distance is worked out.
📐
Big idea: distance

Going from one point to the other is like walking dx across and dy down. Those two walks and the straight line make a right-angled triangle, and Pythagoras worked out (about 2,500 years ago!) that the straight line is √(dx² + dy²). That's exactly what distance() does: Math.sqrt is the square root.

A few more new things:

  • Each firefly now has a state: "drifting", then "flashing", then "done". === asks "are these exactly equal?", and && means "and": both sides must be true. In else if, else means "otherwise": a drifting firefly moves, otherwise, if it's flashing, it glows.
  • touchesLight(fly) returns true or false. It checks your spark first, then loops over every flashing firefly. As soon as it finds a light that's close enough, it returns true, and the function stops right there.
  • startFlash switches the firefly to its happy, glowing pictures and adds one to lit.
  • When a flash is over, flyHome uses animate() to float the firefly up while fading it out (opacity going to 0). animate changes numbers smoothly over time for you.
  • `Lit: ${lit}` uses backticks, so the value of lit gets dropped right into the text.

How far apart are the points (0, 0) and (3, 4)?

dx = 3 and dy = 4, so √(3×3 + 4×4) = √(9 + 16) = √25 = 5.
Walking 3 across then 4 down is 7 steps, but the straight line is shorter. Try √(dx² + dy²).

The music of the night

Let's make every flash sing. js-game-zero can make simple musical notes all by itself with tone.play, so no sound files are needed. Play the game, start a big chain, and listen:

  • tone.play(note, 0.4, { waveform: "triangle", volume: 0.25 }) plays a note for 0.4 seconds. The { … } part is extra options: a waveform is the shape of the sound wave ("sine" is pure and soft, "square" is buzzy and retro), and volume goes from 0 to 1.
  • Notes are named with a letter and an octave number: "C5" is a C, one octave above "C4" (middle C).
  • NOTES is a pentatonic scale: five notes of each octave that never clash. However the chain happens, it sounds pretty!
  • % means "remainder after dividing". (lit - 1) % 10 counts 0, 1, 2 … 9, then wraps back to 0, so a chain of 25 never runs out of notes.
🔇

No sound? Browsers stay silent until you've clicked on the page, so the very first click wakes the sound up. Check your volume too!

Nights, goals and game states

It's a toy. Let's make it a game! Real rules: you get one click per night, and you need to light up enough fireflies to win. Each night gets harder. This step is the biggest one, but it's made of ideas you already know.

Levels are just data

NIGHTS is a list of objects, one per night: { fireflies: 14, goal: 4 }. The rest of the code looks things up with NIGHTS[night].goal. Want a new level? Add a line. No new code needed!

Game states

The game is always in exactly one state, stored in state. The same click means different things in different states: "start" on the title screen, "flash!" while aiming, "next night" after a win. Watch this map light up as you play the game above:

🗺️ The state map
Right now the game is in: (press Run above)
  • onMouseDown is now a chain of if … else if …: it checks the state and does the right thing. The click only makes a spark in the "aiming" state, and that switches the state to "chain", so you can't click twice. || means "or": a click on the title or the finished screen starts from night 1.
  • startNight() fills the sky with fresh fireflies and resets lit and spark.
  • In update, if (state !== "chain") return; leaves early unless a chain is happening (!== means "is not"). Then if (!spark && !anyFlashing()) ends the night once every light is out (! means "not").
  • endNight() compares lit with the goal (>= means "at least") and picks the next state.
  • write() is our own helper for centred text, so drawing words takes one short line each time. Inside, screen.draw.text takes its settings as an object: where its center goes, its size and its color.

Polish: fonts, a jar of light, and saving

The game works! The last step is the sprinkles on top that make it feel finished. This is the complete game, exactly the one you played at the top of the page.

  • A rounded font. Games can carry font files in a fonts folder. Adding fontname: "fredoka" to write() changes every piece of text in the game at once. That's the payoff of making a helper function!
  • A jar of light. fullness is how close you are to the goal, from 0 to 1 (Math.min stops it going past 1). The glow behind the jar grows with it.
  • Left clicks only. onMouseDown(pos, button) can also tell you which button was pressed. In js-game-zero even the scroll wheel counts as a button, so the first line ignores everything except a left click (a tap counts as one too).
  • An aiming ring follows mouse.pos, the mouse's current position, so you can see how far your flash will reach.
  • A night intro. introTimer counts down from 2.5 seconds. While it's above 0, the big "Night 3" message shows.
  • Little tunes. playTune uses clock.schedule(…, delay) to play each note a bit later than the one before. The () => … is an arrow function: a tiny function written right where it's needed.
  • Saving progress. storage.set("bestNight", …) saves a value that's still there next time you play, even after closing the page. The top line reads it back with storage.get("bestNight") ?? 0. The ?? means "or, if nothing was saved yet, use 0".

Words you learned

Coordinates
Two numbers, x (across from the left) and y (down from the top), that name a spot on the screen.
Function
A named set of instructions. draw and update are functions the game calls for you.
Variable
A named box holding a value that can change, made with let.
Constant
Like a variable, but it never changes. Made with const.
Game loop
Update, draw, repeat, about 60 times a second.
dt
Seconds since the last frame. Multiply speeds by it so games run the same everywhere.
if statement
Runs code only when a yes-or-no question is true.
Object
A bundle of named values, like { x: 10, y: 20 }.
Array (list)
An ordered list of values, like [1, 2, 3]. Positions count from 0.
Loop
Code that repeats: for (let i = 0; …) counts, for (const x of list) visits each item.
Actor
A picture with a position that you can move, animate and draw.
State
Which situation the game is in right now (title, aiming, won…), stored in a variable.
