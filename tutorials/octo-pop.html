🐙 Tutorial 5 · Typing and strings

Octo Pop

Build a typing game from a completely empty screen, one small step at a time. Bubbles full of words float up from the sea floor, and Octo the octopus pops each one when you type its word. Along the way you'll learn what programmers call strings: the way every program works with words. The code you'll write is real JavaScript, one of the most popular programming languages in the world.

Big idea: x and y, and painting order

Every spot in the window has two numbers. x says how far across from the left edge. y says how far down from the top. So (0, 0) is the top-left corner, and y gets bigger as you go down.

The computer paints in the order you write the lines, like painting on a canvas. Things painted later cover things painted earlier. That's why the sea comes first and the word comes last.

Next: it's time to find out what a string really is.

Words are strings

The bubble needs a word, and every letter of that word should sit neatly inside it. To do that, the program has to know things about the word: how long it is, and what its letters are. That's what strings are for. Run this step, then try the letter boxes underneath:

The bubble grows to fit its word, and each letter is placed by the program, one at a time.

🔤
Big idea: strings

A string is a row of letters (programmers say characters) threaded together, like beads on a string. Write one with quote marks: "octopus".

A string knows how long it is: bubble.word.length is 7. And every letter has a position number (an index), starting from 0, not 1: bubble.word[0] is "o", bubble.word[1] is "c".

🔘
What's that dot?

A dot reaches inside something. bubble.word is the word that belongs to the bubble, and "octopus".length is a fact the string knows about itself. Strings can also do things, and those abilities are called methods. You write the brackets to make them happen: "octopus".toUpperCase() gives you "OCTOPUS". You'll meet more methods in the steps ahead.

🔢 Letter boxes
Type any word. Every letter gets a number underneath. Slide the position to see what word[i] gives you.
  • LETTER_WIDTH and BUBBLE_PADDING are constants: how many pixels each letter gets, and some spare room around the word.
  • bubble.width = bubble.word.length * LETTER_WIDTH + BUBBLE_PADDING sizes the bubble: 7 letters × 17 pixels + 44 = 163 pixels wide. Longer word, bigger bubble. (* means "times".)
  • The text in the bubble is written by write(text, x, y, size, color), a function of our own. When we call it, we hand it some values called arguments: what to write, where, how big, and what colour. The brackets after function write give each one a name to use inside. Because every piece of text in the game goes through write, changing the font here changes all the text.
  • Inside, screen.draw.text takes the text and then an object of settings in curly brackets. center: [x, y] puts the middle of the text at that spot, fontname: "fredoka" picks the rounded font, and shadow: [0, 2] adds a soft shadow 0 pixels across and 2 pixels down. The shadow's colour, rgb(42, 33, 64, 70), is mixed from red, green and blue light (each from 0 to 255), and the fourth number makes it mostly see-through.
  • drawWord(bubble) draws the word one letter at a time. for (let i = 0; i < bubble.word.length; i++) is a counting loop: i starts at 0 and goes up by 1 (i++) for as long as i < bubble.word.length. So for "octopus" it runs 7 times, with i = 0, 1, 2, … 6.
  • Inside the loop, bubble.word[i] is the letter at position i, and left + i * LETTER_WIDTH is where to draw it: each letter sits one LETTER_WIDTH further right than the one before. left works out where the very first letter goes, so the whole word is centred.

The first letter is number 0, so a word with 7 letters has letters 0 to 6, and word[7] is undefined: there's nothing there. The last letter is always at word.length - 1. Slide the position past the end in the widget to see it.

Next: the bubble floats! Time to meet the game loop.

The game loop: float up

A bubble that stays still isn't much of a bubble. Here's the secret behind every video game: the computer draws a picture, changes things a tiny bit, draws again, changes a tiny bit, draws again… about 60 times a second. Your eyes blend those pictures into motion. That's the game loop. Watch the bubble float:

The bubble rises, sways from side to side, reaches the surface, and starts again from the sand. Keep an eye on bubble.y in the live values box: it counts down, because up is the smaller y.

  • update(dt) is a second special function. The game calls it every frame, right before draw(). update changes things, draw shows them.
  • dt is the time since the last frame, in seconds. It's usually about 0.017 (one sixtieth of a second).
  • bubble.y -= BUBBLE_SPEED * dt; means "take BUBBLE_SPEED × dt away from y". Speed × time = distance, so each frame the bubble moves exactly as far as it should in that sliver of time. (-= is short for bubble.y = bubble.y - ….)
  • if (bubble.y < SURFACE_Y) asks a yes-or-no question: "is the bubble's y less than the surface line's y?". Less y means higher up. If the answer is yes, the part after it runs and puts the bubble back at SPAWN_Y, right above the sand.
  • let time = 0; makes a variable: a labelled box whose contents can change later, unlike a const. time += dt; adds each frame's dt to it, so time is a stopwatch of the seconds since the game began.
  • WOBBLE is a constant for how far the bubble sways, and bubble.startX remembers where the bubble began. Math.sin(time * 2) gives a number that swings smoothly between −1 and 1 as time goes on, like a wave, so WOBBLE * Math.sin(…) moves the bubble between WOBBLE pixels left and WOBBLE pixels right of its starting spot (10 to begin with). The * 2 makes the sway quicker.
🔁
Big idea: the game loop

Every frame, the game calls update(dt) to change things, then draw() to show them. Multiplying a speed by dt means the bubble covers the same distance every second, whether your computer draws 30 frames a second or 144.

A slow computer draws a frame every half second, so dt is 0.5. The bubble is at y = 300 and BUBBLE_SPEED is 30. Where is it after one frame?

30 pixels a second for half a second is 15 pixels, so 300 − 15 = 285. That's the beauty of dt: slow frames take bigger steps.
Multiply the speed by dt first: 30 × 0.5. Then take that away from 300.

Make the bubble float twice as fast: at least 56 pixels a second.

const BUBBLE_SPEED = 60; // pixels per second

Next: one bubble is lonely. Let's fill the sea with them.

A school of bubbles

One bubble is lonely. We want lots, each with its own word, but writing bubble1, bubble2… for each would get tiring very fast. Instead we'll keep a list of bubbles, and let loops do the repetitive work. A new bubble appears every few seconds, with a random word from a list of words.

🧺
Big idea: lists and objects

A list (programmers say array) holds many values in order. This list holds strings: WORDS is ["cat", "sun", "fish", …]. WORDS[0] is "cat", WORDS[1] is "sun": lists count from 0 too. An empty list is [], and .push(…) adds something to the end.

An object bundles named values together, like { x: 80, y: 60 }. Every Actor is an object, and we can stick our own extras onto it, like bubble.word. That's how each bubble in the list carries its own word.

  • let bubbles = []; is a variable holding an empty list, and spawnTimer is a countdown timer: it counts down to the next bubble.
  • makeBubble(word) builds one bubble, like the one from the last step but for any word we give it, and returns it: it hands the new bubble back to whoever asked for it.
  • Inside it, diameter is how wide this word's bubble needs to be, and margin is half of that plus the sway: how far from the walls the middle of the bubble must stay, so the bubble never pokes out of the window. randomInt(margin, WIDTH - margin) picks a random whole number between the two, so bubbles appear in different places.
  • Each bubble gets a random phase, a starting point in the sway wave, so they don't all sway in step. Math.random() gives a random fraction between 0 and 1, so times 6 it's anywhere from 0 to 6.
  • moveBubble(bubble, dt) is the movement code from last step, but it works on whichever bubble we hand it.
  • In update, for (const bubble of bubbles) visits each item of a list in turn, calling it bubble while it's there. That's how every bubble gets moved, and (in drawBubbles) drawn.
  • spawnTimer counts down. When it reaches 0 or less, a new bubble is pushed onto the list with randomChoice(WORDS) (a random item from a list) as its word, and the timer starts again.
  • bubbles.filter((bubble) => bubble.y > SURFACE_Y) builds a new list that keeps only the bubbles for which the test is true: the ones still below the surface. The (bubble) => … is an arrow function: a tiny function without a name. Bubbles that float away are left out, so the list never gets too long.

What does bubbles.filter((bubble) => bubble.y > SURFACE_Y) do with a bubble at y = 50, if SURFACE_Y is 74?

50 is not greater than 74, so the test is false and the bubble isn't kept.
The test is bubble.y > SURFACE_Y. Is 50 greater than 74? Only bubbles that pass the test are kept.

Add it inside the square brackets: "jelly" goes between commas, like the others.

const WORDS = ["cat", "sun", "fish", "crab", "wave", "pearl", "moon", "bell", "kraken"];

Next: a keyboard, and the heart of the game.

Typing makes a string

Now the player joins in. Every key you press will add a letter to a string called typed, and a tray under Octo will show it. Click the game first so it can hear your keyboard, then start typing:

Type some letters and watch the tray, and the live values, fill up. Press Backspace to take one away. Capitals and Caps Lock don't matter, and keys like Shift or the arrows are ignored.

  • ALPHABET is one string holding all 26 letters. The game will use it to check that a key really is a letter.
  • let typed = ""; makes another variable and puts the empty string in it: two quote marks with nothing between them. It's a string with 0 letters, which is exactly how much you've typed so far.
  • onKeyDown(key, unicode, repeat) is another special name: the game calls it whenever a key goes down. key says which key it was, as a number you compare with names like keys.BACKSPACE. unicode is the character the key typed, as a string: "a", or "A" with Shift held. For keys that don't type a character (Shift, the arrows, Enter) it's the empty string.
  • unicode.length === 1 keeps only keys that typed exactly one character. === asks "is this exactly equal to that?". (A single = is different: it puts a value in a box.) The else if means "otherwise, if…".
  • && !repeat adds a second condition. && means and: both sides must be true, so the key has to type one character and not be a repeat. When you hold a key down the keyboard starts repeating it, and the game tells onKeyDown with repeat. !repeat means "not a repeat", so holding a letter key types one letter, not twenty. (Holding Backspace keeps erasing, which is what you'd expect.)
  • unicode.toLowerCase() turns capitals into small letters, so Shift and Caps Lock make no difference. Words in the game are always lowercase.
  • ALPHABET.includes(letter) is true when the letter is somewhere inside the alphabet string. The ! in front means "not", and return leaves the function straight away. So anything that isn't a letter stops here.
  • typed += letter; adds the letter onto the end of typed. += is short for typed = typed + letter.
  • typed.slice(0, -1) is what Backspace does: it cuts a piece out of the string. More on that in a moment.
  • drawTray() draws the tray picture, then writes typed on it. If typed === "", there's nothing to show yet, so it writes a little hint instead.
🧵
Big idea: joining and cutting strings

Strings can be joined with +: "cat" + "fish" is "catfish". And they can be cut: word.slice(start, end) gives you the piece from position start up to, but not including, position end. A negative number counts back from the end, so -1 means "stop one letter before the end". Slicing never changes the original string. It hands you a new one.

Why lowercase everything?

To a computer, "A" and "a" are different letters. By turning every typed letter into lowercase as it arrives, the game never has to worry about it. It's a good habit: tidy up what players give you before using it.

If typed is "ca", what is typed after typed += "t" runs?

+= joins the new letter onto the end. The computer doesn't check if it's a real word. It only glues the strings together.
typed += "t" means typed = typed + "t": join the two strings, then put the new, longer string back in the typed box.

What is "octopus".slice(0, -1)?

It starts at position 0 and stops one letter before the end, so only the final s is cut off. That's exactly what Backspace needs.

Next: bubbles light up when your letters match their words.

Which bubbles match?

Right now typing does nothing to the bubbles. Let's make them react: every bubble whose word starts with the letters you've typed gets a golden ring, and the letters you've already typed turn pink inside it. Type the first letter of a word you can see:

Type c and every bubble starting with "c" lights up. Type a second letter and only the words that still match stay lit. Typed a letter that matches nothing? Nothing lights up. Press Backspace and try again.

  • PINK and GOLD are two new colour constants: pink for typed letters, gold for the ring.
  • isLit(bubble) answers a yes-or-no question about one bubble. A function that returns true or false is perfect for an if to ask.
  • bubble.word.startsWith(typed) is true when the word begins with exactly those letters. "crab".startsWith("cr") is true, but "crab".startsWith("ra") is false. Words that start the same way are said to share a prefix.
  • typed.length > 0 && …: && means and. Both sides must be true. We need the first part because every word starts with the empty string, so with nothing typed, every bubble would light up!
  • In drawWord, done is true for a letter that's inside a lit bubble and whose position is less than typed.length: if you've typed 2 letters, letters 0 and 1 are done. Then done ? PINK : INK is a quick two-way choice: if done is true, use PINK, otherwise use INK.
  • ring is a little bigger than the bubble (bubble.width / 2 is its radius), and screen.draw.circle(…) draws it as an outline, 4 pixels thick, only when isLit(bubble) says so.
🔎
Big idea: does it start with…?

word.startsWith(letters) asks whether one string begins with another, and answers true or false. Typing a word letter by letter keeps asking that question: after "c", "ca", "cat", which words still start with what I've typed?

Next: the payoff, popping a bubble.

Pop!

Time for the main event. When what you've typed matches a whole word, the bubble should pop: it swells, fades away, Octo cheers, and you score points. Type a whole word, letter by letter. (If you slip, the wrong letter stays in the tray until you press Backspace. We'll fix that in the next step.)

Pop! The bubble puffs up and vanishes, Octo's face changes, and the score goes up. Let's see how the code knows a word is finished.

  • findBubble(letters) looks through the list for the first bubble that isn't already popping and whose word starts with those letters. As soon as it finds one it returns it, and the function stops. If the loop ends with no match, it returns null, which means "nothing".
  • At the end of typeLetter, findBubble(typed) finds the bubble you're typing. Then bubble.word === typed asks: is the whole word exactly what's typed? If so, the word is complete, and popBubble(bubble) does the popping.
  • bubble && … guards against null. If nothing matched, bubble is null, and asking null for its word would crash. && means and: both sides have to be true. In an if, null counts as "no" and a real bubble counts as "yes", so when the left side is "no", the right side is never even looked at.
  • popBubble bursts the bubble, empties the tray (typed = ""), adds the word's length to the score (longer words are worth more), and gives Octo a happy face.
  • burst(bubble) uses animate: you name an object and some numbers to head towards, and it changes them smoothly over time. Here scale grows by 40% and opacity fades to 0 (invisible), taking POP_TIME seconds.
  • Once a bubble is invisible, bubbles.filter((bubble) => bubble.opacity > 0) drops it from the list. Bubbles that float up past the surface now burst too, instead of vanishing.
  • setMood(image) swaps Octo's picture and starts moodTimer counting down from 0.6 seconds. In update, when the timer reaches 0, Octo goes back to the idle face.
  • `Score ${score}` uses backticks. Inside a backtick string, ${…} drops the value of a variable straight into the text: a template string.
⚖️
Big idea: comparing strings

=== asks whether two strings are exactly the same, letter for letter, and capitals count: "cat" === "cat" is true, but "cat" === "Cat" is false, and so is "cat" === "cats". That's why we lowercased every typed letter in step 6. startsWith asks "does it begin this way?", and === asks "is it all this?" Together they run the whole game.

Which of these is true?

"crab" begins with "cr", so it's true. The other two compare the whole strings, and neither pair is exactly the same: one has a capital C, the other is a letter short.
=== needs every letter to match, including capitals, and the same number of letters.

Why does the code say bubble && bubble.word === typed instead of only bubble.word === typed?

If you've typed letters that match nothing, findBubble returns null. Without the guard, null.word would crash the game.
Try removing bubble &&, run the game, then type a letter no bubble starts with. What happens?

Next: what happens when you slip up?

Oops! Typos and switching

There's a problem. Type a wrong letter and it stays in the tray until you press Backspace. Real typists make mistakes all the time, and sometimes they change their mind and head for a different bubble. Let's make the game handle both: the tray should clear itself when you slip, and a letter that starts another word should switch to it. Try typing half a word, then the first letter of a different one:

  • typeLetter now asks questions in order, as a chain: if … else if … else. The first question that's true wins, and the rest are skipped.
  • Question 1: findBubble(typed + letter) joins the new letter on, with +, and asks "would some bubble still match?". If yes, typed += letter: carry on with this word.
  • Question 2: no? Then does the letter on its own start a different word? typed = letter throws away the old letters and starts again with this one: you've switched bubbles. (One = puts a value in a box. Three, ===, ask a question.)
  • Otherwise: it's a typo. mistake() empties the tray, resets the streak, and gives Octo the ouch face.
  • streak counts words popped in a row without a typo, and it adds a bonus to the score: bubble.word.length + streak. Three clean pops in a row, then a fourth with a streak of 4, will earn 4 bonus points.
  • if (bubble.word === typed) doesn't need bubble && any more: we only get that far when question 1 or 2 said some bubble matches.
  • In update, if (typed.length > 0 && !findBubble(typed)) clears the tray if the bubble you were typing has floated away. The ! means "not".
🌳
Big idea: ask in order, first yes wins

An if … else if … else chain is a list of questions. The computer asks them top to bottom and does the first one that's true, then skips the rest. else at the end catches everything that's left. Put the most specific question first.

Next: the stakes. What if the bubbles win?

Lives, winning and losing

A game needs stakes. From now on, a bubble that floats all the way to the surface costs a life, three lost lives means the game is lost, and popping enough bubbles wins it. The game is always in one of three situations ("playing", "won" or "lost"), and the code has to know which. Let the bubbles escape for a while, then try again with Enter:

  • MAX_LIVES and GOAL are constants for the rules, and lives and popped are variables that change as you play.
  • let state = "playing"; is the star of this step. state holds a string that says what the game is doing right now.
  • escapeBubble(bubble) bursts the bubble, then if (state !== "playing") return; leaves early unless the game is being played (!== means "is not equal to"). Otherwise, lives -= 1 and, at 0 lives, loseLevel().
  • In popBubble, popped += 1 counts the pop, and if (popped >= GOAL) checks whether you've reached the goal (>= means "at least").
  • startLevel() resets everything for a fresh try and sets state = "playing". winLevel() and loseLevel() switch state to "won" or "lost".
  • onKeyDown now starts with if (state === "playing"): letters only count while you're playing. Otherwise, key === keys.RETURN || key === keys.SPACE asks for Enter or Space (|| means "or"), and calls nextScreen() to start again. onMouseDown lets a click do the same. (The scroll wheel counts as a mouse button too, so button !== mouse.LEFT ignores it.)
  • In update, new bubbles only appear while playing.
  • screen.blit(i < lives ? "heart" : "heart_empty", …) draws a heart for every life in a loop (three, to begin with): full ones for the lives you have left, empty ones for the lives you've lost. A row of dots, filled pink as you pop, shows how close you are to the goal.
  • drawMessages() draws a see-through dark layer over the game with rgb(10, 28, 58, 150) (the fourth number is how solid it is), then a message that depends on state.
🚦
Big idea: game states

A game is always in exactly one state, and a state can be as simple as a string in a variable. The same key press means different things in different states: a letter types while "playing" and does nothing when "won", while Enter does the opposite. Checking state at the top of each special function keeps things tidy.

Levels written as sentences

One level is over quickly. Now let's make five, each with its own words, speed and goal. We could write five copies of the game's rules, but there's a better way: put each level's details in data and let one set of code read it. The words for a level are written as one string, with spaces between the words, and code chops it into a list. Win the first level to meet the second:

Levels are data

LEVELS is a list of objects, one per level. Each object has a name, the words its bubbles use, a speed (how fast the bubbles float up), an every (seconds between new bubbles) and a goal (how many bubbles to pop to clear the level).

The variable level says which level we're on, counting from 0. So LEVELS[level] is the object for the current level, and LEVELS[level].speed is its speed: first pick the object out of the list, then pick the field out of the object. Want a new level? Add an object. No new code needed!

Big idea: split, and levels as data

text.split(separator) turns one string into a list of strings. Writing levels as a sentence of words is friendlier than a list full of quote marks and commas, and it's quick to edit. And keeping a game's levels in a data list means designing a new level takes a few lines.

Polish: title, music and saving

The game works! The last step is the sprinkles on top that make it feel finished. This is the complete game, exactly the one you played at the top of the page. Here's what's new:

  • A title screen. The game now starts with state = "title", and drawMessages shows the name and a hint while bubbles float by behind it. Enter starts the game.
  • Saving your best score. saveBest() checks if (score > bestScore) and, when you've beaten your record, storage.set("bestScore", …) saves it. A saved value is still there next time you play, even after closing the page. It runs whenever you win or lose a level. A line near the top reads it back with storage.get("bestScore") ?? 0: the ?? means "or, if nothing was saved yet, use 0".
  • A musical word. NOTES[(typed.length - 1) % NOTES.length] uses the length of what you've typed to pick a note from a list. The first letter plays the first note, the second letter plays the next one up, and so on, so typing a word plays a little rising tune. The % means "the remainder after dividing": 11 % 10 is 1, so the twelfth letter of a very long word wraps back round to the second note instead of running out. tone.play makes a sound with no sound file needed: a note name, how long, and some options. Typos get a low buzz, and escapes a sad note.
  • Little tunes. playTune uses clock.schedule(…, delay) to play each note a bit later than the one before. The () => … is an arrow function again: a tiny function written right where it's needed.
  • A tentacle zap. When a bubble pops, zap remembers where it was. drawSea draws two thick lines from Octo to that spot, a dark one under a lilac one (screen.line(x1, y1, x2, y2, color, width) draws a straight line between two points), and update forgets the zap after 0.15 seconds.
  • Life in the sea. A fish is a flip-book Actor (two pictures, 6 frames a second) that swims right and starts again on the left. Octo bobs gently with Math.sin, and a streak counter appears when you're on a roll.

Words you learned

String
A piece of text inside quote marks, like "octopus": a row of letters. The empty string, "", has no letters at all, and every string starts with it.
Length
How many letters a string (or items a list) holds: "cat".length is 3.
Index
A letter's or an item's position number. Counting starts at 0, so "cat"[0] is "c".
Joining (+, +=)
Gluing strings end to end: "cat" + "fish" is "catfish".
Slice
Cutting a piece out of a string: "octopus".slice(0, -1) is "octopu".
startsWith
Asks whether a string begins with certain letters: "crab".startsWith("cr") is true.
=== (equals)
Asks whether two things are exactly the same. For strings, every letter and capital must match.
Split
Chops one string into a list of strings: "a b".split(" ") is ["a", "b"].
Template string
A string in `backticks` where ${…} is replaced by a value: `Score ${score}`.
List and object
A list (array) holds values in order, like ["cat", "sun"], and its positions count from 0. An object bundles named values, like { x: 10, y: 20 }.
Loop
Code that repeats: for (let i = 0; …) counts, and for (const x of list) visits each item.
Variable and constant
Named boxes for values. A variable (let) can change later; a constant (const) can't be swapped for something else.
Function
A named set of instructions. draw and update are functions the game calls for you, and the values you hand it when you call it are its arguments.
Method
An action a value can do, written after a dot with brackets: "cat".toUpperCase() gives "CAT".
State
Which situation the game is in right now ("playing", "won"…), kept in a variable.
