A grid of ice tiles

Every puzzle in Penguin Slide happens on a grid — like squared paper, or a chessboard. Grids are everywhere in games: Minesweeper, Tetris, Pokémon, Candy Crush… so this is a trick you'll use again and again.

Each square is a tile. We describe a tile by its row (how far down) and its column (how far across). Like most things in JavaScript, we count them from 0: the top row is row 0, the next is row 1, and so on.

🔁
Quick refresher

draw() runs about 60 times a second and paints the whole screen. screen.rect(x, y, width, height, color) paints a filled rectangle whose top-left corner is at x, y. The point 0, 0 is the top-left of the game; x grows to the right and y grows down.

The magic is two loops, one inside the other. for (let row …) runs once for each row. Inside it, for (let col …) runs once for each column. So the code in the middle runs ROWS × COLUMNS = 60 times — once for every tile.

To place a tile we multiply: x = LEFT + col * TILE. Column 0 sits at LEFT, column 1 is one tile further right, column 2 is two tiles further… and the same idea gives y for rows. (Each tile is drawn 2 pixels smaller than TILE so you can see the gaps.)

A level made of letters

A puzzle needs rocks and fish in particular places. We could write a screen.rect line for every single rock… or we could draw the level with our keyboard!

Look at LEVEL below. It's an array of strings. Each string is one row of the rink and each letter is one tile. Squint and you can see the rink!

  • # rock
  • . ice
  • F fish
  • P penguin

To get one letter we index twice: LEVEL[row] picks one row (a string), and LEVEL[row][col] picks one letter out of it. Then if (letter === "#") decides how to paint it: === asks "are these exactly the same?"

📐
LEVEL.length is the number of rows, and LEVEL[row].length is the number of letters in a row — so the loops automatically fit whatever level you draw. Bigger level? No other code changes needed.

What is LEVEL[1][1]?

LEVEL[1] is the second row, "#P.....#.#", and letter [1] of that is its second letter: "P".
That's LEVEL[0][0] — remember, [1] is the second item.

Meet the penguin

Time to move! The penguin isn't part of the floor any more. It's an Actor — a picture that knows where it is and can move around, just like the fireflies in Firefly Flash.

We give the penguin two extra properties, row and col, so it always knows which tile it's on. Then tileX() and tileY() turn a column or row into pixels, and tileAt(row, col) tells us what's on a tile.

Strings can't be changed once they're made, so loadLevel() copies the level into grid — an array of arrays of letters, made with split("") — and swaps the P for plain ice. The P only tells us where the penguin starts.

When you press a key, onKeyDown(key) runs once. Each arrow calls step(dx, dy): dx is how many columns to move (−1 left, +1 right) and dy how many rows (−1 up, +1 down). If tileAt says the next tile is a rock, return leaves the function early and the penguin stays put.

🧠
Rows go with y, columns go with x Moving right adds 1 to col. Moving down adds 1 to row. Keep an eye on the Live values panel while you move.

keys.W, keys.A, keys.S and keys.D exist, just like keys.LEFT.

|| means "or": if (key === keys.LEFT || key === keys.A) is true for either key.

function onKeyDown(key) {
  if (key === keys.LEFT || key === keys.A) step(-1, 0);
  if (key === keys.RIGHT || key === keys.D) step(1, 0);
  if (key === keys.UP || key === keys.W) step(0, -1);
  if (key === keys.DOWN || key === keys.S) step(0, 1);
}

Slippery ice: the while loop

Here's the twist that makes Penguin Slide a puzzle: on ice, you can't stop! The penguin keeps sliding until the next tile is a rock.

That's exactly what a while loop is for. A for loop repeats a set number of times. A while loop repeats as long as something is true: 

while (tileAt(row + dy, col + dx) !== "#") {
  row += dy;
  col += dx;
}

Read it aloud: "while the next tile is not a rock, take one more step." (!== means "is not".) When the next tile is a rock, the condition is false, the loop ends, and row and col are on the last ice tile before it. Step through it yourself:

Choose a direction to start.

In the code, slide(dx, dy) replaces step(). It copies the penguin's position into row and col, lets the while loop push them along, then moves the penguin to the end in one jump. (Next step, we'll make it glide.)

What would happen if a level had a gap in its outer wall of rocks?

Right. Past the edge, grid[row] is undefined, and asking undefined for a letter is an error. That's why every level is wrapped in rock. Try it: change a # in the wall to ., slide through the gap, read the error… then press ↺ Reset.

Smooth sliding with animate()

Right now the penguin teleports. Let's make it really slide! animate(object, {…}) changes numbers on an object smoothly over time — here, the penguin's x and y. You tell it where to end up, how long to take (duration, in seconds), the style of motion (tween), and what to do when it's finished (onFinished).

🧠
Brain and legs The while loop is the brain: it works out where the penguin will stop, instantly. animate() is the legs: it glides there over time, then calls stopSliding().

Longer slides should take longer, so duration = distance × SLIDE_TIME. distance counts tiles; Math.abs turns negative numbers positive, so sliding 3 tiles left is a distance of 3, not −3.

While the penguin glides, sliding is true and slide() returns straight away — otherwise you could start a new slide halfway across a tile! And if you press towards a rock you're already touching, distance is 0: no move, just a bonk(), which squashes the penguin (scale 0.82) and lets a "spring" tween boing it back to normal. Game-makers call little touches like this juice.

🏁 Tween race
Every penguin slides the same distance in the same time — only the tween is different. Which one feels the most like ice?

Why is the duration distance * SLIDE_TIME, instead of the same time for every slide?

Yes! With a fixed duration, short slides would crawl and long ones would zoom. Try setting the slider very high to see each slide in slow motion.
Imagine a 1-tile slide and a 9-tile slide that both take half a second. Which one moves faster?

Give the slide a different tween. Try "easeOut" (glides to a gentle stop), "bounce" (bounces off the rock) or "accelerate" (picks up speed).

Fish, and how to win

A penguin's gotta eat. Fish become Actors too, each with row, col and an eaten flag, kept together in the fishes array.

Every frame, update() asks: is the sliding penguin touching a fish? penguin.touches(fish.pos) is true when the middle of the fish is inside the penguin's picture. That fish is eaten — and the penguin keeps sliding, so you can gobble fish on the way past.

After each slide, stopSliding() counts the fish left. None? You win! state switches from "playing" to "won", and slide() ignores the keys from then on. A variable like state is how games keep track of which "mode" they're in. The win message sits on a white box from screen.draw.filledRect, which takes the box as a list: [left, top, width, height].

〰️
A wiggle for free Each fish's angle is Math.sin(time * 5 + fish.col) * 12. Math.sin swings smoothly between −1 and 1 as time passes, so the fish rocks between −12° and 12°. Adding fish.col makes neighbouring fish wiggle out of step.

Why does stopSliding() call eatFishUnderPenguin() again, when update() already checks every frame?

Exactly. The animation can finish between two update() calls, so we check once more before deciding whether you've won.
Think about the very last tile of a slide — the order things happen in a frame matters.

Snow, water holes — and your own level

Two new tiles make the puzzles much more interesting:

  • * snow: the penguin sinks in and stops on it
  • O water hole: splash! The level starts again

Both are new rules inside the while loop. After each step, if (…) break; checks the tile we just slid onto. break jumps straight out of the loop, so the slide ends right there. || means "or", so tile === "*" || tile === "O" is true for either one.

Then stopSliding() looks at where we landed. A hole calls fallIn(), which spins and shrinks the penguin and uses clock.schedule(restartLevel, 1.2) to start the level again 1.2 seconds later. Notice there are no brackets after restartLevel: we're handing over the function itself, for the clock to call later. You can also press R to restart any time.

The rings that puff out for snow, splashes and fish are effects: each one grows and fades for 0.6 seconds, then filter drops it from the list.

Undo, stars and saving

        
Three features that make a puzzle game feel finished:

        

          ⭐ Stars. starsFor(moves, par)
          gives 3 stars for matching par, 2 stars for up to half as many moves again, and 1 star
          for any win. Math.ceil rounds up to a whole number, so with a par of 3,
          Math.ceil(3 * 1.5) is 5 moves for two stars.
          drawStar() draws a
          star as a polygon whose 10 points alternate between far out (the tips) and close in
          (the dips). Math.cos, Math.sin and Math.PI place those points
          around a circle; you can use the function without following the maths.
          screen.draw.filledPolygon fills the shape and screen.draw.polygon outlines it.
        

        

          ↶ Undo. Before every move,
          snapshot() writes down everything
          the move could change — where the penguin is, which fish are eaten, the move count —
          and pushes it onto
          history. Press Z and
          undo() pops the last snapshot off and
          puts everything back. A list you only add to and take from the top of is called a
          stack.
        

        

          💾 Saving. storage remembers small things even after you
          close the page. When you win,
          best keeps your fewest moves
          for that level and unlocked
          remembers the furthest level you've reached. At the start,
          loadLevel(unlocked) carries on
          where you left off. clamp(value, low, high)
          keeps a number between two limits, in case the saved level is from a version of the game with
          more levels.

Glossary

        

          
Grid

          
Rows and columns of equal-sized tiles. Tile (row, col) sits at x = left + col × size, y = top + row × size.

          
Nested loop

          
A loop inside a loop. The inner one runs completely, every time the outer one goes round once.

          
Array

          
A list in order, inside [ ]. list[0] is the first item; list.length counts them.

          
Object

          
Named values bundled inside { }, like { name: "Snow Day", par: 2 }.

          
while loop

          
Repeats as long as its condition is true. break leaves it early.

          
Actor

          
A picture with a position that can move, turn, scale, fade and check what it touches.

          
animate()

          
Smoothly changes numbers on an object over time, with a tween for the style of motion.

          
State

          
A variable saying what "mode" the game is in, like "title", "playing" or "won".

          
Stack

          
A list you add to and take from the top of: last in, first out. Perfect for undo.

          
storage

          
js-game-zero's memory that survives closing the page, for progress and high scores.

          
Par

          
The fewest moves that solve a level, found by trying every possible move in order (a "breadth-first search").
