🥞 Tutorial 4 · Falling things and wobbly towers

Pancake Stack

A bear chef, a sky that rains pancakes, and a tower of breakfast that gets taller… and wobblier… with every catch. Slide under the pancakes, don't let three of them hit the ground, and see how high you can stack. You'll build the whole game yourself, one small step at a time, right here in this page.

  • ⏱ About 2 hours
  • 🌱 Total beginners welcome (a little quicker after Firefly Flash)
  • 💻 Nothing to install — the code runs in this page

Here's what you'll make. Click the game, then slide the bear with ← → (or A D), or point with the mouse or a finger. Catch pancakes on the plate. Every full stack of ten is served for bonus points. Miss three and it's game over!

A sunny morning

Every game starts with an empty window, and you decide what goes in it. Ours begins with a bright morning: a sky, a sun, some hills and a field of grass. Here's your entire first program. Press Run:

Good morning! Let's read it line by line.

  • WIDTH = 720; and HEIGHT = 480; set the size of the window in pixels. They need capital letters, because the game looks for those exact names.
  • TITLE is the game's name. Words go inside quote marks, which makes them a string.
  • function draw() { … } is a function: a named recipe. The game follows it about 60 times every second to paint the picture, like the pages of a flip book.
  • Lines that start with // are comments: notes to remind people what the code does. The computer skips them.

Big idea: x and y

Every spot in the window has two numbers. x says how far across from the left edge. y says how far down from the top. So (0, 0) is the top-left corner, and y gets bigger as you go down. That surprises everyone at first!

Meet the bear

A sunny morning needs someone to enjoy it. Meet Bear, our chef. Here's all the art for the game: every picture is a file in the game's images folder, and you use it by its name.

Bear has three faces: bear_idle for most of the time, bear_happy after a catch and bear_ouch after a miss. We'll start with the calm one.

  • const FLOOR = 455; makes a constant: a box with a label on it. FLOOR is the y of the ground under the bear's feet. Giving a number a name makes the code easier to read: FLOOR says far more than 455 does.
  • const chef = new Actor(…) uses new, which means "make a brand new one", to make an Actor: a picture that remembers where it is. "bear_idle" is the picture's name (the file bear_idle.svg without the ending).
  • midBottom: [WIDTH / 2, FLOOR] says which part of the picture to put at that spot: its middle-bottom, the bear's feet. WIDTH / 2 is half the width: the middle of the screen. The computer does the maths for you. The { … } around it is an object: a bundle of named options. The [ … ] holds a list of two numbers: x, then y.
  • drawScenery() is the scenery from last step, moved into a function of its own so draw() stays short. Now draw() only calls it, then draws the bear with chef.draw().

Big idea: names for things

Programmers give things names. const makes a name for a box you fill once: you can't swap what's in it for something else. (chef is a constant too: its box always holds the same bear, although the bear itself can move around.) let, which you'll meet soon, makes a box you can refill, and function makes a name for a recipe. A good name tells you what something is.

A bear that can't move is a statue. Let's fix that.

Slide, bear, slide

Everything so far has been a still picture. To make things move, a game does what a flip book does: it shows a picture, makes a tiny change, shows the next picture, and does that about 60 times a second. First it updates the world, then it draws it. Click the game, then press the ← and → keys:

  • function update(dt) is the other function the game calls for you, right before every draw(). Anything that should change goes in it.
  • dt is short for "delta time": the number of seconds since the last frame. At 60 frames a second it's about 0.0167.
  • keyboard.left is true while the left arrow is held down, and false the rest of the time. The if checks it: if the left key is down, do this.
  • chef.x -= CHEF_SPEED * dt means "make chef.x smaller by this much". The dot in chef.x reaches inside chef to get the x that belongs to it, and * is how code writes "times". (-= is short for "subtract from itself"; += adds.) Smaller x is further left.
  • clamp(chef.x, EDGE, WIDTH - EDGE) squeezes a number into a range. If chef.x tries to go past the EDGE on either side, it's put back at the edge. The bear can't leave the window. (A single = means "work out the right-hand side first, then put the answer in the box on the left", which is why chef.x can appear on both sides.)
  • The numbers sit at the top as constants with a note on each, so you can play with them: CHEF_SPEED and EDGE.
⏱️
Big idea: speed × dt

Why not write chef.x -= 8? Because a faster computer runs more frames a second, and the bear would zip about on it. Instead we say how far the bear goes in a second and multiply by dt to get this frame's share: 460 × 0.0167 ≈ 7.7 pixels now, and 60 frames later it adds up to 460 pixels. Every computer agrees.

🧪
Break it on purpose

Mistakes are normal, and the computer tells you where they are. In the editor, delete the ) right after keyboard.left in the first if line and press Run. A friendly red message points at the line. Put the bracket back (or press ↺ Reset) and the game wakes up again.

Why does the code multiply the speed by dt?

Yes. dt is the time a frame takes, so speed × dt is the distance covered in that frame: the same bear on a fast or slow computer.
Try the numbers: 460 pixels a second, with 60 frames a second. How many pixels is each frame's step?

What is clamp(700, 60, 660)?

700 is above the biggest allowed number (660), so clamp hands back 660.
clamp(value, min, max) returns the value, unless it's too small (then min) or too big (then max).

Lots of players like A and D better than the arrows. Make both keys slide the bear too.

Keys are great on a computer, but a phone has no arrow keys. Next: pointers.

Follow the pointer

Phones and tablets have no arrow keys, but everyone has a mouse or a finger. So let's make the bear chase the pointer. Move your mouse over the game (or drag a finger across it), and the bear slides after it. The arrow keys still work too!

  • let targetX = WIDTH / 2; is a variable (made with let, because it will change) for where the bear is heading. The bear's real position, chef.x, chases it.
  • onMouseMove(pos) is a hook: the game calls it every time the pointer moves, and passes the spot as pos, a list of two numbers. pos[0] is the first one: x. (Lists count from 0, so pos[0] is the first and pos[1] the second, y.) Fingers and pens count as pointers too.
  • onMouseDown runs when you press. if (button !== mouse.LEFT) return; says "if it wasn't the left button, stop here". (!== means "is not the same as". The scroll wheel counts as a button too, and we don't want it steering the bear.)
  • The keys now move the target instead of the bear, and clamp keeps the target inside the edges.
  • const maxStep = CHEF_SPEED * dt; is the furthest the bear may travel this frame. It's a const made inside the function, so it's a brand new box every frame. Then chef.x += clamp(targetX - chef.x, -maxStep, maxStep); moves it towards the target by the distance left, but never more than maxStep.
🎯
Big idea: chase a target

Instead of jumping to where you want, step towards it. targetX - chef.x is how far there is to go. clamp limits it to a small step each frame, so the bear glides at its top speed, and when it's closer than one step it arrives exactly with no wobbling back and forth.

The bear can go anywhere. Now let's give it something to chase.

Pancakes from the sky

Here's the main event: a pancake, falling from the sky. When it falls off the bottom of the screen, another one starts again from the top. Slide the bear around and watch it fall past.

  • makePancake() is a function that builds something. It makes a new Actor, up above the screen at y = -30 (negative y is above the top edge), and at a random x: randomInt(EDGE, WIDTH - EDGE) picks a whole number between the two, both included.
  • return newPancake; hands the finished pancake back to whoever called the function, like a baker handing you your order.
  • let pancake = makePancake(); keeps the current pancake in a variable. It's let because we'll swap in a fresh pancake later.
  • pancake.y += PANCAKE_SPEED * dt; is the bear's trick again: speed × dt. But we add to y, because y grows as you go down.
  • if (pancake.y > HEIGHT + 30) asks "has it fallen past the bottom of the screen?", and if so, a brand new pancake takes its place.
  • The bear's moving code now has its own name, moveChef(dt), and update(dt) calls it, then looks after the pancake. As the game grows, update becomes a list of jobs.
🧺
Big idea: functions can make things

A function can return a value, so the line that called it gets something back: makePancake() becomes a pancake. When the same job is needed in lots of places (and soon it will be), put it in a function and give it a good name.

A pancake falls at PANCAKE_SPEED = 140 pixels a second. How far does it fall in 2 seconds?

Distance = speed × time: 140 × 2 = 280. Every frame adds a thin slice of that, 140 × dt.
Multiply the speed (pixels per second) by the number of seconds.

Pancakes fall right through the bear. We need some rules.

Catch it!

Time for the rule that makes this a game. When a pancake falls down to the height of the plate, the code looks at where the bear is: if the plate is underneath, the pancake is caught, and if not, it sails on by. Slide under the pancakes and watch the score climb. Click the game first so it can hear your keys.

  • stackTop() answers "how high is the top of the plate?". chef.top is the y of the top of the bear's picture (every Actor knows its top, bottom, left and right edges), and the plate's surface is PLATE_DEPTH pixels below that.
  • pancake.bottom >= stackTop() is true once the pancake's bottom edge has reached the plate. (>= means "greater than or equal to": y gets bigger going down, so a bigger y means it has fallen further.) We only check while the pancake's state is "falling". state isn't something Actors come with: we stuck our own label on each pancake (newPancake.state = "falling"), so it can remember what's happening to it. === asks "is it exactly the same as…?", and && means and: both sides must be true.
  • Math.abs(pancake.x - chef.x) is how far apart they are sideways. (Math is a built-in toolbox of number helpers.) Math.abs drops any minus sign (Math.abs(-50) is 50), so it doesn't matter which side the pancake is on. If that is less than CATCH_RANGE, it's caught!
  • A catch adds one point with score += 1 and starts a new pancake. Everything after an if that you want to run together goes inside { … } curly brackets. (With only one line to run, the brackets can be left out, as we did in the last step.)
  • Otherwise, the else part runs and the pancake's state becomes "missed". That way it's not checked again as it falls, and nobody gets credit for catching it halfway down the bear!
  • write(text, x, y, size, color) is our own helper for drawing words. The five names in its brackets are slots that get filled in order by whoever calls it: write("Hi", 110, 34, 28, "white") means text "Hi", centred at x 110, y 34, size 28, in white. Inside it, screen.draw.text(text, { … }) does the work, and its options say where the middle of the words goes (center), how big they are (size), their colour, the round font (fontname) and a dark outline so they stay readable. (size: size means "the option called size gets whatever is in our slot called size".) `Score: ${score}` is a template string: the ${score} becomes the score's number. (The backtick ` key is usually top-left of the keyboard, next to 1, or directly above Tab.)
⚠️
One equals sign or three?

A single = sets a value: score = 5 puts 5 in the box. Three, ===, asks a question: is it exactly the same? Mixing them up is one of the most common mistakes in all of programming. If a game does something odd after an if, check the equals signs first.

📏
Big idea: "close enough" is a distance

Games decide whether things touch by measuring how far apart they are, then comparing with a limit. Here it's only the sideways distance: Math.abs(a - b) < limit. Try the widget: drag the pancake over the plate, and change the limit.

One pancake at a time is slow. Let's make it rain.

A rain of pancakes

One pancake at a time is a slow breakfast. We want a whole rain of them: a new one every second or so, with several in the air at once. That needs two new tools. A countdown timer that says "time for the next pancake!", and a list that keeps track of all the pancakes that are falling.

  • let falling = []; makes an empty list (programmers say array). It will hold every pancake that's in the air, and falling.length says how many that is right now (the Live values panel shows it). .push(…) adds something to the end of a list.
  • PANCAKE_PICTURES is a list of three picture names. randomChoice(…) picks one at random, so the pancakes come in plain, blueberry and chocolate-chip flavours.
  • spawnTimer -= dt; makes spawnTimer a countdown: each frame, a little time drains out of it. if (spawnTimer <= 0) says "is it less than or equal to zero? Then time's up!". Then a new pancake goes into the list, and spawnTimer = SPAWN_GAP winds the timer up again.
  • for (const pancake of falling) is a loop: it runs the code inside once for each pancake in the list, with pancake standing for the one it's on. (A name made inside a function or a loop belongs only to it, so it's fine that other functions use pancake for their own pancake.) Every pancake falls, and every pancake gets the catch-or-miss decision from last step.
  • The decision has moved into two small functions with a parameter: landPancake(pancake) and missPancake(pancake). The pancake you hand in is the one the function works on. Later steps add more to each.
  • const stillFalling = [];: a fresh, empty list for the pancakes that are still in the air. Inside the loop, a pancake only goes into it with stillFalling.push(pancake) if it hasn't landed (!== means "is not") and hasn't fallen off the bottom. At the end, falling = stillFalling swaps the lists over, and the landed and lost pancakes are gone.
  • Drawing is a loop too: for (const pancake of falling) pancake.draw();.
🧺
Big idea: lists and loops

A list holds many things; a loop does something with each one. Together they let you write the code for one pancake once and have it work for ten, or a hundred. And a timer that counts down to zero and starts over is how games make things happen on a schedule.

            Multiplying the swing by WOBBLE * index * index
            says how far: the sideways distance in pixels. index is how high
            the pancake is, and using it twice means the top of a tall tower swings far more
            than the bottom, as a real one does. The bottom pancake (index 0) never sways: it only moves with the bear.
          
    • 
          
  • 
            pancake.x = chef.x + sway(i);
            puts each pancake at the bear's x, plus its own sway.
          
    • 
          
  • 
            topX() is "the x where the next
            pancake would land": the bear's x plus the sway of the next slot, sway(stack.length).
            A tower of 4 fills slots 0 to 3, so the next pancake will go in slot 4, which is stack.length.
            And now Math.abs(pancake.x - topX())
            is the catch test, so a pancake only counts if it lands on the swaying top. The plate hasn't moved, but the
            target has.

          🌊
          

            Big idea: sine waves make smooth swings
            

              Anything that goes smoothly back and forth (swaying, bobbing, pulsing, blinking) is
              a job for Math.sin. Feed it a number that keeps growing, like
              time, and you get a number that cycles from −1 to 1. Multiply it by a
              size, and you have motion with exactly the size and speed you want.

Three strikes

        

          So far, missing a pancake costs you nothing. A game needs something to lose. We'll give
          you three lives: miss a third pancake and it's game over, with a
          chance to play again. That means the game needs to know what's happening right
          now, playing or lost, which is called its state. Let a few
          pancakes drop past the plate and see what happens.
        

        

        
    
          
  • 
            misses counts the pancakes you've
            lost, and MAX_MISSES is how many you can afford.
            misses += 1; goes in
            missPancake, and if (misses >= MAX_MISSES) endGame();
            ends the game. (>= means "greater than or equal to".)
          
    • 
          
  • 
            let state = "playing"; is the game's
            state:
            a word in a variable. (You've met this idea already: each pancake has its own state,
            "falling", "landed" or "missed". Now the whole game gets one.)
            endGame() changes it to "lost"
            and clears the pancakes still in the air. startGame() puts everything
            back to the beginning and sets the state to "playing".
          
    • 
          
  • 
            if (state !== "playing") return;
            is the heart of a state: the part of update below it, spawning and moving pancakes, only runs
            while playing. return leaves the function early. Notice the bear's moving
            and the tower's swaying are above it, so they carry on in every state.
          
    • 
          
  • 
            In startIfWaiting(), a press restarts the game when it's
            "lost". A click (see onMouseDown) or the
            Space or Enter key calls it (keys.RETURN is the Enter key).
            || means "or".
          
    • 
          
  • 
            The hearts: a counting loop draws one heart per
            life. cond ? a : b picks one of two values: a full
            "heart" while i is below the lives we have left, an
            "heart_empty" after that.
            screen.blit(picture, [x, y]) paints a picture with its top-left corner at x, y.
            The x is worked out from the number of lives, so the hearts line up along the right edge however
            many lives there are.
          
    • 
          
  • 
            drawMessages() writes the "Oh crumbs!" screen
            when the state is "lost", with a see-through dark rectangle over the game. The colour comes from
            rgb(42, 33, 64, 120), which mixes red, green and blue
            (each from 0 to 255) plus a fourth number for how solid it is: 255 is solid, 0 is invisible.

            Big idea: game states
            

              A game is always in exactly one state, and each state decides what
              the code does: what update does, what gets drawn, what a click means.
              Adding a screen later (a title, a pause) means adding one more word and a few
              ifs. That's how nearly every game you've played is built.

          Right now pancake number one hundred falls exactly like pancake number one. Real kitchens
          get busier: breakfast is gentle, lunch is frantic. We could write
          if after if for each stage, but there's a neater way: put the
          numbers in a table, and let the code look things up in it.
        

        

        
    
          
  • 
            RUSHES is a list of
            objects.
            Each object is a row of the table: a name, the score it
            starts from, how fast pancakes fall (speed) and how long
            to wait between them (gap). As with chef.x, a dot reads one part of a row:
            rush.speed.
          
    • 
          
  •

            "which row are we on?". It starts with the first row, then loops down the list, calling each row
            candidate in turn. Whenever the score has reached a candidate's from
            (score >= candidate.from), that row becomes the answer. The
            last row the score reaches wins.

  •

            catch, updateRush() compares it with

Words you learned

        

          
Pixel
One of the tiny dots a screen is made of. This game is 720 pixels wide and 480 tall.

          
Coordinates
Two numbers, x (across from the left) and y (down from the top), that name a spot on the screen.

          
String
A piece of text, written inside quote marks, like "Pancake Stack".

          
Comment
A note for people, starting with //. The computer skips it.

          
Function
A named recipe. draw and update are called by the game; you can write your own, like makePancake(), and some give a value back with return.

          
Variable & constant
A named box for a value. A let box can be refilled, like score; a const box keeps what you first put in, like WOBBLE.

          
Actor
A picture with a position that you can move, scale, fade, swap and draw.

          
Game loop & dt
Update, draw, repeat, about 60 times a second. dt is the seconds since the last frame: multiply speeds by it.

          
Parameter
A name in a function's brackets that is filled in by whoever calls it, like pancake in landPancake(pancake).

          
if statement
Runs the code after it only when the question in its brackets is true. else says what to do when it isn't.

          
Hook
A function with a special name, like onMouseMove, that the game calls when something happens.

          
Clamp
clamp(value, min, max) squeezes a number into a range. It keeps things on screen and limits each step of a chase.

          
Timer
A variable you subtract dt from each frame. When it reaches zero, something happens and the timer starts again.

          
Array (list)
An ordered list of values in [ ]. push adds to the end, length counts, and positions count from 0.

          
Loop
Code that repeats. for (const x of list) visits every item; for (let i = 0; …) counts.

          
Template string
Text in `backticks` where ${…} is replaced by a value, like `Pancakes: ${score}`.

          
Arrow function
A small function with no name, written where it's needed: () => { … }.

          
Object
A bundle of named values in { }, like { name: "Brunch", from: 25 }.

          
State
A variable saying which situation the game is in: "title", "playing" or "lost".

          
Sine wave
Math.sin turns a growing number into a smooth swing between −1 and 1. It's the heart of every sway, bob and pulse.

          
Data table
Rows of numbers (here, RUSHES) that the code looks things up in, so changing the game means editing a table, not rewriting code.

          
animate & tween
animate glides numbers on an object to new values over time. The tween is the style of the motion.

          
storage
js-game-zero's memory that survives closing the page, for scores and progress.
