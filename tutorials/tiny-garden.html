Tiny Garden

Plant a seed, water it, watch it grow, pick the flower and sell it to buy rarer seeds. You'll build this cosy little garden from a completely empty screen, one small step at a time. Nothing can go wrong in it, and nobody is in a hurry.

  • ⏱ About 2 hours
  • 🌱 Total beginners welcome (no other tutorial needed first)
  • 💻 Nothing to install — the code runs right on this page

Play it first

Press Play, then click the garden. Click an empty plot to plant a seed. A little raindrop means it's thirsty, so click the plant again to water it. When a flower blooms it glows: click it to pick it. Then click the stall to sell what's in your basket, and spend your coins on rarer seeds from the shelf at the bottom. Can you grow every flower?

A sunny patch

Every game needs a window to happen in. In js-game-zero (the small game engine that runs everything on this page) you open one with a few lines. Here's your entire first program. Press Run:

A blue sky, a glowing sun and a stripe of grass. Let's read it line by line.

  • WIDTH = 640; and HEIGHT = 400; set the size of the game window in pixels. They must be written in capitals, exactly like that, because the game looks for those exact names.
  • TITLE is the game's name. Words go inside quote marks, which makes them a string.
  • function draw() { … } is a function: a named recipe. The game runs draw about 60 times every second to paint the picture, like the pages of a flip book.
  • Lines that start with // are comments: notes to remind people what the code does. The computer ignores them.
  • screen.fill paints the whole window. Given two colours, it fades from the first (at the top) to the second (at the bottom). Colours like "#aee6ff" are hex codes. Plain names like "gold" or "hotpink" work too.
  • screen.circle(560, 50, 38, "#ffd34d") draws a filled circle. The numbers and colour mean: x, y, radius (how far it reaches from its middle), and colour.
  • The sun's glow is a bigger circle drawn first. Its colour is rgb(255, 236, 160, 70): a mix of red, green and blue light (each from 0 to 255). The optional fourth number is how solid it is: 0 is invisible and 255 is solid, so 70 is mostly see-through.
  • screen.rect(0, 144, WIDTH, 256, "#9bd160") draws a filled rectangle: the x and y of its top-left corner, its width, its height, and its colour. We used WIDTH for the width, so the grass always stretches all the way across.
🧠
Big idea: x and y

Every spot in the window has two numbers. x says how far across from the left edge. y says how far down from the top. So (0, 0) is the top-left corner, and y gets bigger as you go down. That surprises everyone at first!

The game loop: a drifting cloud

Here's the secret behind every video game. The computer draws a picture, changes things a tiny bit, draws again, changes things a tiny bit, draws again… about 60 times a second. Your eyes blend those pictures into motion. That's the game loop. Press Run and watch the cloud:

Watch the Live values box while it runs: cloudX changes every frame!

  • update(dt) is a second special function. The game calls it every frame, right before draw(). update changes things, draw shows them.
  • dt is the time since the last frame, in seconds. It's usually about 0.017, which is one sixtieth of a second.
  • const CLOUD_SPEED = 14; is a constant: a box whose contents never change. We write it in capitals to say "this is a setting you can tune".
  • cloudX += CLOUD_SPEED * dt; means "add CLOUD_SPEED × dt to cloudX". Speed × time = distance, so each frame the cloud moves exactly as far as it should in that sliver of time.
  • if (cloudX > WIDTH) cloudX = -100; is a decision. The part in brackets is a yes-or-no question: is cloudX greater than WIDTH? If yes, the rest of the line runs and the cloud jumps back to the left, hidden off the edge of the window. If no, it's skipped.
🔁
Big idea: the game loop

Each frame the game does the same two jobs: update(dt) nudges the numbers a little, then draw() paints a picture from those numbers. Nothing "moves" by itself: it's a flip book, and update decides what each page looks like.

We multiply by dt because not every computer manages 60 frames a second. A slow one takes fewer, bigger steps, and a fast one takes more, smaller ones, but the cloud arrives at the same place at the same time on both.

CLOUD_SPEED is 14. A slow computer takes a frame that lasts dt = 0.5 seconds. How far does the cloud move in that one frame?

14 × 0.5 = 7. Half a second of drifting at 14 pixels a second is 7 pixels.
Multiply the speed by the time: CLOUD_SPEED * dt.

Big idea: lists and loops

A list (programmers say array) holds many things in order. let plots = []; makes an empty one, and plots.push(plot) adds something to the end.

A loop runs the same lines again and again. Lists and loops go together like seeds and soil.

  • new Actor("soil_dry", { topLeft: [x, y] }) makes an Actor: a picture that knows where it is. The part in curly brackets, { topLeft: [x, y] }, is an object: a bundle of named settings (there's more about objects in the next step). topLeft says which corner of the picture goes at that spot.
  • for (let row = 0; row < ROWS; row++) is a counting loop: start row at 0, keep going while row is less than ROWS, and add one (row++) each time round. It runs its inside ROWS times.
  • Inside it, for (let col …) is another loop. Loops inside loops are called nested: for every row, the inner loop runs through every column. That's ROWS × COLUMNS = 8 plots.
  • GARDEN_LEFT + col * PLOT_STEP_X places a plot: column 0 sits at GARDEN_LEFT, column 1 is one plot-step further right, column 2 is two steps further… and the same idea gives the y of each row.
  • makePlots(); at the very bottom runs the function once, when the game starts.

Big idea: state

A thing's state is which situation it's in right now. Every plot is always in exactly one state, kept as a word: "empty" to begin with, then "growing" once there's a seed in it. Watch plots[0].state in the Live values box as you click. (plots[0] is the first plot in the list: the one in the top-left corner.)

  • Actors let us stick on extra facts of our own: plot.state and plot.seed. The second one says which flower is planted there, as a position in the SEEDS list.
  • SEEDS is a list of objects. Each object is one kind of flower: { name: "Daisy", image: "daisy", … } is a bundle of named values. You read a value with a dot, like seed.name. For now there's only the daisy, and we'll use most of its values later.
  • selected is which seed packet you'll plant, as a position in the list. Positions start at 0, so 0 means the first flower: the daisy.
  • onMouseDown(pos, button) is a third special function. The game calls it whenever you press the mouse button (or tap the screen), and pos is where. The first line, if (button !== mouse.LEFT) return;, ignores anything but the left button (!== means "is not equal to"), because the scroll wheel counts as a button too. return means "stop here and leave the function", so a click from any other button does nothing.
  • The loop in onMouseDown asks every plot plot.touches(pos) and hands the lucky one to tendPlot(plot).
  • if (plot.state === "empty") asks whether the plot is empty. === means "is exactly equal to". Only then does plantSeed(plot) change the state to "growing".
  • In drawPlot, if (plot.state === "empty") return; means "an empty plot has nothing more to draw, so leave the function early". Otherwise screen.blit("seed", …) paints a seed on the soil.
🐞
One equals sign or three?

= puts a value into a box: plot.state = "growing". === asks a question: plot.state === "empty". Mixing them up is one of the most common mistakes there is. If an if misbehaves, check how many equals signs it has.

Growing up: timers

Plants take time. Time in a game is a number you keep adding to, exactly like the cloud's position. Plant a few seeds and wait:

Each seed becomes a sprout, then a bud, then a daisy, four seconds after it was planted. Here's the machinery.

  • Each plot now has plot.growth: how many seconds it has been growing.
  • growPlot(plot, dt) runs for every plot, every frame (the loop in update calls it). if (plot.state !== "growing") return; skips plots that aren't growing (!== means "is not equal to").
  • plot.growth += dt; is the same trick as the cloud: add a slice of time every frame, and growth counts up in seconds.
  • SEEDS[plot.seed].grow looks up how long this flower takes. plot.seed is a position in the list, so SEEDS[plot.seed] is the daisy's object, and .grow is its 4 seconds. When plot.growth >= … is true (>= means "at least"), the state becomes "ready".
⏱️
Big idea: a timer is a number

A timer is a number that changes with time. To count up, add dt every frame. To check whether a time is up, compare it with a limit using >=. That's all "growing" is: a number climbing towards 4.

  • The picture changes as it grows. STAGES is a list of picture names, from newly planted to nearly in bloom.
  • plantImage(plot) picks the right one. progress is growth ÷ grow: 0 when planted, 1 when ready, and 0.5 when it's halfway. STAGES.length is how many names are in the list (3), so multiplying the progress by it gives a number from 0 up to 3. Math.floor chops off everything after the decimal point (it rounds down), so 1.7 becomes 1. STAGES[1] is "sprout".
  • Once the plot is "ready", return seed.image shows the finished flower instead.

Thirsty plants: watering

Let's make the plants need a drink. A newly planted seed starts out thirsty, and shows a raindrop. Click it to water it: the soil darkens and the plant grows for a few seconds, until the water runs out. Daisies are quick, so one drink is enough for them, but slower flowers will need several. Press Run, plant a seed, then click it again:

Watch the Live values: wet counts down while growth counts up, and when wet hits zero, growth stops.

  • Each plot has a new fact, plot.wet: the seconds of water it has left. WATER_TIME is how many seconds one drink gives.
  • waterPlot(plot) fills the plot up: plot.wet = WATER_TIME;
  • In tendPlot, else if adds a second possibility. Read it as: "if the plot is empty, plant a seed; otherwise, if it's growing, water it."
  • In growPlot, if (plot.wet <= 0) return; says "no water left? Stop here: nothing grows". Otherwise plot.wet -= dt; counts the water down while plot.growth += dt counts the growth up. (-= subtracts, and <= means "at most".)
⏳
Big idea: counting up and counting down

Timers come in two flavours. A stopwatch counts up from zero: growth climbs until it reaches the target. A countdown starts full and falls to zero: wet drops until it hits zero. Two small numbers, and a plant has a whole life.

Big idea: one click, three jobs

Look at tendPlot now. It's a chain of questions about the plot's state. Whichever matches first decides what a click does: empty plants, growing waters, ready picks. A thing that moves between a few named states, with rules for each move, is called a state machine. Games are full of them.

Big idea: adding things up with a loop

To add up a whole list, start a running total at zero and add each item as the loop visits it: 

let total = 0;
for (const kind of basket) {
  total += SEEDS[kind].price;
}

Each kind in the basket is a position in SEEDS, so SEEDS[kind].price is what that flower sells for. total += … adds it to the total. When the loop ends, the total is the whole basket's worth. Then coins += total; pays you and basket = []; empties the basket with a fresh empty list.

Big idea: data tables

SEEDS is a table: a list where every item is an object with the same named values. The list's position picks the row (SEEDS[2]), and a dot picks the column (SEEDS[2].price). Games keep almost everything that can change (levels, enemies, prices) in tables like this, so changing the game means changing data, not code.

Big idea: rules are questions

Almost every rule in a game is a question with an if. "Can I buy this?" is coins >= seed.cost. If the answer is yes, the buying code runs. If no, a different part runs instead. Even a "no" gets an answer here: the shop tells you what the seed costs, so you always know what to do next.

  • owned is a list of true/false values, one for each flower in SEEDS. makeOwned() fills it in when the game starts: seed.cost === 0 is true only for a seed that costs nothing, which is why the daisy is the one you start with.
  • chooseSeed(index) now has three branches. if (owned[index]): you already have it, so choose it. else if (coins >= seed.cost): you can afford it, so coins -= seed.cost takes the coins, owned[index] = true unlocks it, and it's chosen. Otherwise (else): you can't, so say what it costs.
  • Nothing bad happens if you can't afford a seed: you get a message and that's all. This is a game with no way to lose.
  • !owned.includes(false) checks the whole list: owned.includes(false) is true if any value is false, and ! flips it, so the test passes once no locked seeds are left. That's the "garden complete" message.
  • slot.icon.opacity = owned[i] ? 1 : 0.4 fades the pictures of locked seeds. In drawShelf, owned packets show what they sell for, and locked ones show the coin and the cost.

You have 30 coins and click the Sunflower packet, which you don't own yet and costs 100. What happens?

The else branch runs: say(…) shows the price, and your coins and packets stay as they were.
The buying code only runs when coins >= seed.cost is true. 30 is not at least 100.

Big idea: tweens

A tween slides a number smoothly from where it is to where you want it. animate(plot, { hop: 0, duration: 0.5, tween: "bounceEnd" }) says: "change plot.hop to 0 over half a second, bouncing like a dropped ball". Set hop to −14 first and the plant starts 14 pixels up and bounces down into place. Any number can be tweened, and the tween name picks the style.

  • tone.play("C5", 0.1, { waveform: "triangle", volume: 0.25 }) makes a sound without any sound file. Give a note name (C5 is a note, C6 is the same note higher up), how many seconds it lasts, and some settings: the waveform is the sound's flavour, and volume goes from 0 to 1.
  • playTune(notes) plays a list of notes one after another. clock.schedule(…, delay) runs something later, and i * 0.1 makes note 0 wait 0 seconds, note 1 wait 0.1, note 2 wait 0.2, and so on. The () => … is an arrow function: a tiny function with no name, written right where it's used.
  • plot.hop is a new fact on every plot: how far it's lifted up. drawPlot adds it to the plant's y, and plantSeed, waterPlot and growPlot kick it with a tween.
  • bob makes a ready flower sway gently up and down, with Math.sin and the time stopwatch again.
  • floatText(words, x, y) makes a little "+8" message. It's a plain object with a y and an opacity, and animate tweens both: up 40 pixels while fading out. floaters.filter(…) in update keeps only the ones that haven't faded away yet: the (floater) => floater.opacity > 0 part is another arrow function, a tiny test that answers "is this one still visible?" for each floater in turn. drawHud draws the ones that are left.
  • When you can't afford a seed, the packet wobbles: it's tilted 8 degrees and then tweened back with the springy "spring" style.

In playTune, what does i * 0.1 do?

With i counting 0, 1, 2, 3, the notes start at 0, 0.1, 0.2 and 0.3 seconds.
It's the second thing handed to clock.schedule: the delay, in seconds, before the function runs.

A title screen, and a garden that remembers

The finishing touches are a proper welcome and a garden that's still there tomorrow. This is the complete game, exactly the one you played at the top of the page. Play for a bit, then press Run again: the garden comes back as you left it!

  • state is the whole game's state, a word like each plot has. It starts as "title". if (state === "title") in onMouseDown changes it to "playing", and a click that starts the game doesn't also plant a seed because of the return that follows.

💾
Big idea: save the facts, not the pictures

storage.set("garden", …) saves a value in the browser, so it's still there next time. But it can only keep plain things: numbers, words, true/false, lists and objects made of them. A plot is an Actor with a picture attached, and a picture can't be saved.

So saveGarden() copies out only the facts that matter (state, seed, growth and wet for every plot, plus your coins, owned seeds and basket) into plain lists and objects. loadGarden() does the reverse: it reads the facts back and puts them onto fresh plots.

  • storage.get("garden") returns what was saved, or nothing if this is a first visit. if (!saved) return; means "nothing saved? Then there's nothing to load": ! means "not".
  • hasSaved lets the title screen say "Welcome back!".
  • The garden saves after every click (saveGarden() at the end of onMouseDown) and also clock.scheduleInterval(saveGarden, 5), which runs a function again and again, here every 5 seconds, so growth is saved even when you're only watching.

Why does saveGarden copy out each plot's state, seed, growth and wet, rather than saving the plots themselves?

Anything storage keeps must be plain: numbers, words, true/false, lists and simple objects. The facts are all it needs to rebuild the plot later.
Think about what a plot actually is: an Actor, with a picture and position as well as the facts we added.

Words you learned

Coordinates
Two numbers, x (across from the left) and y (down from the top), that name a spot on the screen.
Function
A named set of instructions. draw and update are functions the game calls for you.
Variable
A named box holding a value that can change, made with let.
Constant
Like a variable, but it never changes. Made with const.
Game loop
Update, draw, repeat, about 60 times a second.
dt
Seconds since the last frame. Multiply speeds by it so games run at the same pace everywhere.
Timer
A number that changes with time: it counts up like a stopwatch (growth) or down like a countdown (wet).
if / else
Runs code only when a yes-or-no question is true, and else says what to do when it isn't.
List (array)
An ordered list of values, like [1, 2, 3]. Positions count from 0.
Object
A bundle of named values, like { name: "Daisy", price: 3 }.
Loop
Code that repeats: for (let i = 0; …) counts, and for (const x of list) visits each item.
Actor
A picture with a position that you can move, draw and ask whether it touches something.
State
Which situation something is in right now (empty, growing, ready…), kept in a variable.
Data table
A list of objects that all have the same named values, like SEEDS. Adding a row adds a thing to the game.
Tween
A smooth change of a number over time, made with animate.
Storage
A place to keep plain values between visits, so a game can remember.
